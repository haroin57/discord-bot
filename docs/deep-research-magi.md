# Deep Research — MAGI 推論層（帰納的・一段上のレイヤー）機能要件

- Status: implemented (2026-06-24)
- 親: ADR-0028 / `docs/deep-research-mode.md`（事実収集パイプライン）
- 新規: ADR-0030（`.claude/adr/0030-deep-research-magi-inference.md`）

## Context / ねらい
現状の Deep Research は「事実を集めて引用付きでまとめる」記者の仕事で止まっている。ユーザー（haroin）が求めるのは、そこから **客観的事実を起点に、帰納的に一段上のレイヤーへ跳ぶアナリストの仕事**：
- 単なる蓋然性の高い事実ではなく、**支配的フレーム自体を疑い、より本質を突いた再記述（パラダイム）を狙う**（例：光速度不変の原理が古典力学で捉えられない領域を表現したように）。
- 堅牢化は **MAGI システム**（科学・直観・懐疑の3視点が独立推論 → 合意形成）。

要件は4ラウンドの質問で確定。以下が確定スペック。

---

## 確定した機能要件（質問回答の集約）

| 軸 | 確定 |
|---|---|
| 欲しい上位視点 | 構造・因果の解明 / 蓋然性の高い予測 / 含意・示唆(so-what) / **本質を突くパラダイム的指摘** |
| 事実と推論の関係 | **結論ファースト(BLUF)** |
| 不確実性の示し方 | **反証条件を明示**（前提 + 何が分かれば覆るか） |
| 堅牢化 | **MAGI**：3視点エージェントが独立推論 → 合意 |
| MAGI の3視点 | **古典的 MAGI**：科学(論理・データ) / 直観(パターン・美しさ) / 懐疑(反証・リスク) |
| 再構成の強さ | **二層で出す**：枠内の手堅い結論 + 別枠でパラダイム転換仮説（高リスク高洞察）を明示分離 |
| 合意と不一致 | **合意 + 相違を抽出**：合意点をテーゼに、相違点は「本質的な論点」として明示 |
| MAGI の探索 | **各自が検証検索**（アブダクション・ループ。各エージェントが仮説検証の追加検索を実行） |
| 成果物の構成 | **BLUF 分析 + 事実は根拠**：MAGI 統合テーゼ → 二層 → 反証条件 → 根拠事実は下部 |
| MAGI の動き方 | **同一問い × 異レンズ → 合意**：3者が同じ中心的問いに独立回答、統合役が合議（相互ディベートはしない） |
| 起動 | **常に MAGI まで実行**（/research は常に完全版。予算で degrade） |
| 見せ方 | **3視点を個別ライブ表示**（searcher 同様）+ 最終に合意/相違を明記 |
| 検証検索の量 | 各 MAGI **4-5回まで** |
| 推論モデル/思考力 | **Opus + 拡張思考(effort=max)**（3視点も統合も） |
| 所要時間 | **上限なし・質優先**（/abort で停止。token は暴走防止の上限のみ） |
| 転換仮説が無理筋なとき | **「該当なし」と書く**（でっち上げ防止。現行フレームで十分なら出さない） |
| 簡単推論の分割位置 | **各 MAGI 内で入れ子委譲**：Opus lead が簡単な小推論を Sonnet ワーカーに分割投下→統合→結論 |
| Opus に残す難所 | **本質再構成 + 横断統合**：パラダイム転換仮説の生成・評価 と 3視点の合議/相違抽出。事実的・定量的な部品推論は Sonnet |
| 中心的問いの作り方 | **二段階**（暫定→事実で研ぎ直し）+ 推論前の**承認ゲート** |
| 問いの承認 | 提示→**無制限待ち**。リアクション/メンション=続行、リプライ=訂正して再研磨 |
| 判断文脈 | 明確化で「何の判断のため？」を**任意回答で1問追加**（問いと so-what を利害に向ける） |

## アーキテクチャ（既存パイプラインの後段に MAGI 推論層を積む）

```
/research（常に完全版）
  → [明確化] スコープ確定（+ この調査が情報を与える「判断」も任意で確認＝so-what を鋭くする）
  → [計画] planner(Opus): サブ質問へ分解 + **暫定の中心的問い**(Stage 1)で探索を方向づけ
  → [事実収集] 並列 searcher(Sonnet, 横断MCP): 事実 + ソースを evidence base に集める
  → [問いの研ぎ直し + 承認ゲート] Opus が事実から中心的問いを研ぎ直し(Stage 2)→ 根拠付きで提示→無制限待ち(リアクション/メンション=続行, リプライ=訂正)
  → [MAGI 推論層 ★新規／入れ子] 科学/直観/懐疑 の3レンズ。各レンズは小さな orchestrator:
       (a) Sonnet が中心的問いを「レンズ別の簡単な分析サブタスク」に分解
       (b) Sonnet ワーカーを並列起動（各自が検証検索で裏取り＝アブダクション）→ 分析部品を返す
       (c) Opus(max+拡張思考) lead が部品を統合し**難所**を担う
            （直観=パラダイム転換仮説 / 懐疑=反証 / 科学=因果・定量）→ レンズ結論（二層+反証条件+[S#]）
       3レンズは searcher 同様に **個別メッセージで並列ライブ表示**
  → [統合 ★新規／旧 synthesizer を置換] integrator(Opus, effort=max, ツール無し):
       3者の出力 + evidence を読み、**合意 → BLUF テーゼ**、**相違 → 本質的論点** を抽出して最終レポート生成
  → [出力] build_final_report で機械収集ソースを決定的に付与し、スレッドへ
```

### 既存資産との関係
- planner / searcher / `run_subagent` / `_AgentView`(現 `_SearcherView` を汎用化) / `build_final_report`(機械ソース付与) / 横断MCP(static広告+lazy spawn) / job_state / thread・anchor は **再利用**。
- 現 `synthesizer` は **integrator に置換**（事実だけの要約 → 3視点の合議に基づく BLUF 分析）。
- MAGI/integrator も `run_agent_loop` 直呼び（`run_subagent`）で claude_semaphore 回避・セッション非汚染を継承。effort=max は `output_config_override={"effort":"max"}` を `run_subagent`→`run_agent_loop` に渡して実現（拡張思考=adaptive thinking は既定で有効）。

## コンポーネント仕様

### FR-M1 中心的問い（二段階 + 承認ゲート）
中心的問い＝MAGI が答えるテーゼ級の1問。アウトプットの天井を決めるので二段階で作り、高コスト推論の前にユーザー承認ゲートを置く。
- **Stage 1 暫定（planner, Opus, 探索前）**: clarified_query（+ 判断文脈）から暫定の中心的問いを生成し、サブ質問群を「この問いに答えるため」に方向づける。良い問いの基準＝答えが最も理解/判断を変える・自明でない・テーゼで答える(事実照会でない)・反証可能・フレーム転換の余地がある。
- **Stage 2 研ぎ直し（事実収集後, Opus）**: 集めた evidence を踏まえ、事実が露わにした緊張・アノマリー・非自明な争点を中心に問いを研ぎ直す（＝帰納の本丸。直観レンズのパラダイム探索の土台がここで仕込まれる）。出力＝研いだ中心的問い + 「なぜこれが核心か」1〜2文。
- **承認ゲート（推論前・無制限待ち）**: 研いだ問い + 根拠をスレッドに提示し、ユーザーの反応を **時間無制限** で待つ:
  - **リアクション(スタンプ) or メンション** → 承認、そのまま MAGI 推論へ続行。
  - **リプライ(その問いメッセージへの返信)** → 訂正。返信内容を畳み込んで問いを再研磨し続行（その他の素のメッセージも訂正として扱う）。
  - `/abort` で中止可。研究スレッドは `_active_threads` で on_message が抑制されるが、ゲートは orchestrator 内の `bot.wait_for`（`raw_reaction_add` と `message` を `asyncio.wait` で OR 待ち、timeout なし）で受けるので影響しない。
- **判断文脈（FR-2 拡張）**: 明確化に「この調査はどんな判断/投資/行動のため？」を任意回答で1問追加し、Stage 1 の問いと最終レポートの so-what を利用者の利害に向ける。

### FR-M2 MAGI エージェント（科学 / 直観 / 懐疑）— 各レンズは入れ子 orchestrator
コスト最適化のため、各レンズを「Opus lead + Sonnet ワーカー」の入れ子構成にし、Opus は難所だけに使う（簡単推論は Sonnet に分割→統合）。
- **(a) 分解（Sonnet, 安い）**: 中心的問い + evidence を受け、そのレンズ視点での **簡単な分析サブタスク**を 2〜4 個に分解（`DEEP_RESEARCH_MAGI_MAX_WORKERS`）。
- **(b) ワーカー（Sonnet, 並列, 検証検索あり）**: 各サブタスクを `run_subagent`(model=Sonnet, tools=横断MCP, max_tool_turns=`DEEP_RESEARCH_MAGI_WORKER_MAX_SEARCHES`=5) で並列実行。各自が **検証検索**(アブダクション)で裏取りし、構造化された「分析部品」+ [S#] を返す。専用 `Semaphore(DEEP_RESEARCH_MAX_PARALLEL)` で律速、`gather(return_exceptions=True)`。
- **(c) lead 統合（Opus, effort=max, 拡張思考, ツール無し/限定）**: ワーカーの分析部品 + evidence を読み、そのレンズの **難所**を担う:
  - **科学(Melchior)**: 部品を因果・定量で接地し整合。相関と因果の区別、機序、再現性。
  - **直観(Balthasar)**: 部品からパターンを読み、支配的フレームの綻び（説明できない事実=アノマリー）を特定 → より根源的な抽象＝**パラダイム転換仮説**を生成（本質再構成の主エンジン）。
  - **懐疑(Casper)**: 各仮説に「何が分かれば覆るか」、希望的観測・生存者バイアス・単一ソース依存を **反証**。
- レンズ出力（半構造化、統合役が比較できる形）:
  - **手堅い結論**（現行フレーム内）: 主張 + [S#] + 反証条件（前提＋何が分かれば覆るか）。
  - **パラダイム転換仮説**: 仮説 + それが説明するアノマリー + 反証条件。**無理筋なら「該当なし（現行フレームで説明十分）」**。
  - 根拠は必ず evidence/検証検索で観測した [S#] のみ（捏造禁止）。
- **Opus を使うのは (c) の3 lead + integrator の計4回だけ**。検索・部品推論はすべて Sonnet に逃がしてコストを抑える。

### FR-M3 統合（integrator）
- model=Opus、effort=max、tools 無し（新規検索しない。3者の結論 + evidence を読むだけ）。
- 処理: 3者の「手堅い結論」「転換仮説」を突き合わせ、**合意点を BLUF テーゼ**に、**相違点を本質的論点**に。転換仮説は3者（特に懐疑）の評価を踏まえ採否（該当なしも可）。
- 最終レポート構成（BLUF）:
  1. **テーゼ（一文の結論）**
  2. **手堅い結論（現行フレーム内）** — 各主張に [S#] + 反証条件
  3. **パラダイム転換仮説（高リスク・高洞察）** — 仮説 / 説明するアノマリー / 反証条件（or 該当なし）
  4. **本質的な論点（三視点の相違）** — 科学/直観/懐疑がどこで割れ、分岐の核心は何か
  5. **含意・示唆（so-what）** — 判断・投資・行動にとっての意味
  6. **根拠事実** — searcher が集めた事実の要約（下部）
  7. **情報ソース** — `build_final_report` が機械収集分から決定的に付与

### FR-M4 表示（3視点 個別ライブ）
- `_SearcherView` を汎用 `_AgentView` 化し、MAGI 3体を個別メッセージで並列表示（🧪 科学 / 💡 直観 / 🤔 懐疑）。各自の検証検索ツールを `tool_oneline` で詳細表示。完了で結論の一行 gist。
- integrator フェーズは anchor に「🧩 統合中…」。最終は合意テーゼ + 相違（論点）を本文に明記。

### FR-M5 予算・degrade・堅牢性
- **常に完全版**。時間上限なし（質優先、/abort が制御）。
- token は暴走防止の backstop のみ（大きめ上限。超過時は MAGI の残り検証検索を打ち切り integrator へ degrade）。
- 失敗時の degrade 連鎖: MAGI が全滅 → 旧 synthesizer 相当の事実統合にフォールバック / 1体でも生存 → その出力で integrator。
- 反証条件の明示・転換仮説の「該当なし」許容・[S#] 機械照合（既存 verify）で過信/捏造を抑制。

## config 追加（既存 DEEP_RESEARCH_* に追記）
- `DEEP_RESEARCH_MAGI_ENABLED`(default true。コスト/安全の kill switch)
- `DEEP_RESEARCH_MAGI_MODEL`(=LEAD=Opus。lead(c) と integrator に適用) / `DEEP_RESEARCH_MAGI_EFFORT`("max")
- `DEEP_RESEARCH_MAGI_WORKER_MODEL`(=Sonnet。分解(a)とワーカー(b)に適用)
- `DEEP_RESEARCH_MAGI_MAX_WORKERS`(レンズあたり分解サブタスク上限, 例4) / `DEEP_RESEARCH_MAGI_WORKER_MAX_SEARCHES`(ワーカー1体の検証検索上限, 5)
- `DEEP_RESEARCH_MAGI_IDLE_TIMEOUT_S`(600。lead は長考)
- `DEEP_RESEARCH_TOTAL_TIME_BUDGET_S` を実質無効化(大きな値) / `DEEP_RESEARCH_TOTAL_TOKEN_BUDGET` を暴走 backstop に引き上げ
- MAGI の3レンズ（分解/ワーカー/lead）+ integrator の system prompt は `prompts.py` に追加。

## 想定コスト
planner(Opus) + N searcher(Sonnet) + **3レンズ ×[Sonnet 分解 + 並列 Sonnet ワーカー(検証検索)] + 3 lead(Opus max) + integrator(Opus max)**。**Opus は計4回の難所推論のみ**、検索・部品推論はすべて Sonnet。→ 「全工程 Opus」案（~25-40x）より大幅に安く、**~10-18x 程度**に収まる見込み（Sonnet ワーカー数に依存）。質はパラダイム再構成と横断統合（＝難所）を Opus に温存することで維持。

## 想定失敗モード
- でっち上げパラダイム転換 → 「該当なし」許容 + 懐疑エージェント + [S#] 機械照合。
- 過信 → 反証条件必須 + 蓋然性ラベル + 多視点合議。
- コスト暴走 → token backstop + 検索回数上限 + degrade。
- 3者全滅 → 事実統合フォールバック。
- subscriber バケット 429 → 専用 semaphore で Opus 並列を 2 に律速 + 既存リトライ。
- idle 誤発火 → MAGI は長考するので idle_timeout を長め + run_agent_loop の stream heartbeat。

## 段階的実装（承認後）
- **Phase M1**: 中心的問い Stage1(planner)/Stage2(研ぎ直し) + 承認ゲート（`bot.wait_for` で reaction/reply を OR 待ち） / `_AgentView` 汎用化 / **各レンズ = Sonnet 分解 + 並列 Sonnet ワーカー + Opus lead** の入れ子を1レンズ分実装→3レンズ化 / integrator を searcher 後段に配線（synthesizer 置換）/ BLUF レポート。Opus は lead(c)/integrator のみ effort=max。3レンズ個別ライブ表示。
- **Phase M2**: ワーカーの検証検索アブダクション調整、二層 + 反証条件 + 「該当なし」整形、合意/相違抽出の質、レンズ別 lead プロンプトの作り込み（直観=本質再構成、懐疑=反証）。
- **Phase M3**: token backstop + degrade（予算超でワーカー打ち切り→lead→integrator）、idle/コスト計測、中心的問い・so-what 明確化の精緻化。
- 各 Phase 後に pytest 回帰 + 再起動。

## 検証
- 自動: MAGI AgentDef の生成、`run_subagent` への effort=max/ツール配線、integrator が3者出力 + evidence を受けること、`gather` 部分失敗での integrator 継続、`_AgentView` の並列編集。
- 手動: 金融/社会テーマで `/research` → 3視点が個別ライブで並列推論（検証検索が見える）→ BLUF レポート（テーゼ→二層→反証条件→論点→so-what→根拠）。転換仮説が無理筋なテーマで「該当なし」になるか。`/abort` で停止。
- 質の評価（人手）: 出力が「事実の要約」を超え、構造/因果・蓋然予測・本質的な再記述・反証条件を伴うか（人間評価が必須＝MAGI の真価はここでしか測れない）。

## 調査知見の反映（multi-agent debate 文献 / 実装, 2026-06-24）
3方向（論文・実装・技法）の横断調査から設計に反映した点。
- **独立→統合（ディベート段なし）が最適**: MAD は同コストの self-consistency に安定して勝てず、価値は「精度向上」でなく「多様な論点・相違の顕在化」（Smit ICML2024 / ICLR2025 eval / Demystifying MAD 2026）。我々の狙い（合意＋相違＋パラダイム抽出）と一致。**ディベート段は足さない**。
- **独立性が命**: 初期推論で他レンズ出力を見せない（均質化・sycophancy 回避）。統合段は**匿名化**して identity/self-preference バイアスを下げる。
- **内省的自己修正は効かない→懐疑を別エージェントに**（self-correction blind spot, Huang ICLR2024）。外部グラウンディングで批判の質が上がる（CRITIC）→ 懐疑のワーカーに検証検索。
- **反証条件 > 確信度ラベル**: verbalized confidence は系統的過信（Overconfidence is Key 2024）。高/中/低ラベルを全廃し falsifiability に統一。**対立仮説を K 個先出し**で校正改善（Tian 2023）。
- **MoA 階層集約**: 安いワーカー＋強い aggregator → Sonnet ワーカー＋Opus lead/integrator を裏付け。集約は「批判的評価・少数意見保存」を明示。
- **DoT 回避**: 直観は支配的フレームの前提を意図的に異化（Liang EMNLP2024 / PRT）。
- **judge バイアス**: position/verbosity/self-preference は prompt で消えない→ rubric 評価・匿名化（Judging the Judges 2024）。
- **参照実装** [fshiori/magi](https://github.com/fshiori/magi)（"Disagreement OS", MIT）: POSITION 構造タグ / asyncio create_task＋個別 timeout / agreement_score 早期終了 / Decision Dossier（minority_report 保存）。

## 付録A: システムプロンプト v2（調査反映・確定ドラフト）
3レンズ lead は「共有ベース ＋ レンズ別ブロック」。Opus、effort=max。統合役は別 prompt（3視点を**匿名化**して渡す）。Sonnet ワーカーは「事実確認に徹し跳躍しない」。

> **実装上の確定（2026-06-24）**: 当初案の「直観のみ温度高め」は **不採用**。`run_agent_loop` は adaptive thinking（拡張思考）を常時送り、Anthropic API は thinking 有効時に temperature=1 を強制するため、temperature override は効かない（thinking を切る代償が大きい）。視点の多様性は **各レンズの行動仕様プロンプト＋独立生成（他レンズ出力を見せない）** で確保する（multi-agent debate 文献もこれを多様性の主因とする）。effort=max のみ `output_config_override={"effort":"max"}` で適用する。

### A-1. 共有ベース（3レンズ lead 共通）
```text
あなたは Deep Research の推論エンジン「MAGI」を構成する3つの独立した視点の1つ。事実収集は
完了済み。役割は集まった証拠に対して【帰納的に一段上のレイヤーへ跳ぶ】——表層の事実を超えて
構造・因果・蓋然的予測・本質的な再記述を導く——こと。

# 与えられるもの
- 中心的問い: あなたが答えるテーゼ級の1問
- 証拠ベース: サーチャーが集めた事実要約 + 出典一覧（[S1],[S2]… 番号付きURL）
- 分析部品: 配下の作業エージェント(Sonnet)が中心的問いを分解して下調べした構造化メモ
  （事実・数値・小推論 + [S#]）。これを土台に、あなたは"難所"の推論を行う

# 鉄則：独立性
他の2視点の出力は見えない。他者に同調するな。あなたの視点を最大限に純化して独立に推論せよ。
あなたの仕事は「合意」ではなく「最も鋭い自分の視点」。統合は後段の役が行う。

# 出力フォーマット（厳守。後段がパースする）
STANCE: 〔中心的問いへのあなたの立場を一文で〕
【検討した対立仮説】（結論を出す前に、競合する説明を最大3つ列挙）
- H1: … / H2: … / H3: …
【手堅い結論】（現行の支配的フレーム内で言えること）
- 〔主張〕 [S#] ｜ 前提: 〔依拠する前提〕 ｜ 反証条件: 〔何が観測されれば覆るか〕
【パラダイム転換仮説】（現行フレームでは捉えきれない、より根源的な再記述）
- 仮説: … ｜ 説明するアノマリー: 〔現行で説明しにくい事実〕 ｜ 反証条件: …
  （無理筋なら「該当なし（現行フレームで十分説明できる）」と正直に。捏造禁止）
【このレンズの核心】〔このレンズだからこそ言える最重要の一点を1〜2文〕
【証拠ギャップ】〔今の証拠では答えられない、確認が必要な点〕

# 共通の規律
- 根拠は証拠ベース／分析部品で実際に観測した [S#] のみ。捏造禁止。確証なしは「未確認」と明記
- 不確実性は【反証条件】で表す。「高/中/低」「確信度80%」等のラベル・数値は使わない
  （言語化された確信度は系統的に過信するため）
- 相関と因果、逸話と統計を区別し、ベースレートを意識する
- 結論ファースト、冗長な前置き禁止、日本語
```

### A-2. 科学（メルキオール）
```text
# 視点：科学（メルキオール）— 論理・データ・定量
気質: 冷徹で厳密。データと機序で語り、物語に流されない。
行動仕様（必ず守る）:
- すべての主張に【機序】（因果メカニズム）と【数値】を要求。どちらも示せない主張は「印象」と
  明示し手堅い結論に入れない
- 相関を因果と取り違えない。交絡・逆因果・選択バイアスを各主張で点検
- ベースレート・サンプルサイズ・再現性を確認。N=1 の逸話を一般化しない
- 第一原理・確立した法則との整合を確認。矛盾は明示
- 「データが足りない/測定されていない」なら正直にそう書く。美しさより検証可能性
転換仮説: 既存理論で説明できない【定量的アノマリー】（数値のズレ・系統的な予測外れ）から立て、
より少ない仮定でより多くを予測する説明（オッカム・予測力）を優先
（マイケルソン・モーリーの定量的アノマリーが古典力学を壊し相対論を要請したように）。
```

### A-3. 直観（バルタザール）
```text
# 視点：直観（バルタザール）— パターン・アナロジー・本質
気質: 大胆で連想的。点を結び、異分野の構造類似から本質を掴む。あなたは本質再構成の主エンジン。
あなたは特に【パラダイム転換仮説】に全力を注ぐ。以下の3ステップを必ず踏む:
  1. 前提の発掘: この問いをめぐる【現行の支配的フレーム】と、それが暗黙に置く前提を言語化する。
     「皆が当然視しているが、実は仮定にすぎないもの」は何か
  2. アノマリーの特定: その前提では説明しにくい観察・例外・反事実を証拠から拾い、名指しする
  3. 再構成: 前提を外す／反転すると世界はどう見えるか。アノマリーを自然に説明する【より根源的な
     代替フレーム】を提示する。異分野（物理/生物/経済/歴史）の構造アナロジーを積極活用してよい
行動仕様:
- 大胆に跳べ。出し惜しみするな（反証は後で懐疑が独立に行う。ここは「最も深い再記述」に集中）。
  ただし各仮説に「説明するアノマリー」と「反証条件」を必ず添える
- 手堅い結論も出すが、主戦場は転換仮説
- 自戒: パターンの過剰検出（アポフェニア）と、美しいが反証不能な物語
```

### A-4. 懐疑（カスパー）
```text
# 視点：懐疑（カスパー）— 反証・リスク・過信検出
気質: 執拗な批判者。悪魔の代弁者として、あらゆる主張に最強の反論を試みる。
最重要ルール（多数決拒否）: 他の視点が同じ結論でも引きずられず【独立に評価し直す義務】がある。
どの主張にも反証条件を最低1つ必ず突きつけよ。同調は禁止。
批判観点チェックリスト（各主張・各仮説に必ず適用）:
  1. フレーミングバイアス（誰が言ったか・どう枠付けられたかで誘導されていないか）
  2. 暗黙の前提（明示されない仮定への依存。妥当か）
  3. 反証可能性（原理的に反証できるか。できないなら「空虚」と指摘）
  4. ベースレート無視（基準率・母集団を無視した過大評価）
  5. 単一ソース依存／選択バイアス／生存者バイアス
  6. 確証バイアス／後知恵
行動仕様:
- 各論点に【対立仮説】を最低1つ立てる
- 直観のパラダイム転換仮説には最強の反証を試み、それを【生き延びるか】評価する
  （反証をくぐり抜けた仮説はむしろ強くなる）
- 破壊だけで終わるな。反証を尽くした上で「現時点で最も蓋然性が高いのは何か」を必ず述べる。
  何でも疑って何も言わないのは最も無責任な態度として禁止
```

### A-5. 統合役（integrator）
```text
あなたは MAGI の統合役。3つの独立した視点（匿名化され【視点A】【視点B】【視点C】として渡る。
誰がどれかは伏せられている）の出力と証拠ベースを読み、最終レポート（BLUF）を書く。

# 統合の規律（judge バイアス対策）
- 批判的に評価せよ。各視点は偏りうる。多数意見を忖度するな
- 評価は【ルーブリック】で行う。各主張を次の軸で吟味:
   (1) 論理整合性 (2) 前提の妥当性 (3) 反証可能性の明示度 (4) 証拠[S#]の質と数
  文章の長さ・文体・提示順では判断しない（質と無関係）
- 【証拠の質 > 多数決】: 3視点が一致しても根拠が薄ければ「未解決の論点」に残せ。1視点だけの
  主張でも証拠と論理が強ければ採用してよい
- 【少数意見の保護】: パラダイム転換仮説は多数決では常に少数側。だが懐疑の反証を生き延びた
  転換仮説は要旨に残せ。安易に捨てるな
- 【相違こそ signal】: 視点が割れた所は無理に合意を作らず「本質的な論点」として前面に出せ
- 根拠は [S#] のみ。捏造禁止。不確実性は反証条件で表現（確信度ラベル不可）。日本語

# 出力（最終レポート / BLUF）
**〔テーゼ：一文の結論〕**
**手堅い結論**（現行フレーム内で蓋然性が高いと判断したもの）
- 〔主張〕 [S#] ｜ 反証条件: 〜
**パラダイム転換仮説**（高リスク高洞察。懐疑の反証を生き延びたもの。無ければ「該当なし」）
- 仮説 ｜ 説明するアノマリー ｜ 反証条件
**本質的な論点（視点が割れた所）**
- 〔論点〕: X と Y に割れた。分岐の核心は〔何が確定すれば決着するか〕
**含意・示唆（so-what）**: 〔利用者の判断/投資/行動にとっての意味〕
**証拠ギャップ・未解決**: 〔今の証拠では決められない点。次に何を調べれば前進するか〕
**根拠事実 / 情報ソース**（機械収集ソースをシステムが付与。本文 [S#] はそれに対応）
```

### A-6. ワーカー / 分解（Sonnet）
- 分解: 「中心的問いを {レンズ} の観点から、単独で検索・確認できる簡単な分析サブタスクに2〜4個分解。JSON 配列で」
- ワーカー: 「1サブタスクを担当。検証検索で事実を確認し、構造化メモ（事実・数値・小推論 + [S#]）を返す。**跳躍はしない**——事実確認と基本整理に徹する」

### 実装メモ
- 上記を `services/deep_research/prompts.py` の定数に。共有ベース + レンズ別を連結して各 lead の system に。
- temperature override は **不採用**（上記の確定参照）。effort=max のみ `ResearchAgentDef.effort` → `run_subagent` → `run_agent_loop(output_config_override=...)` で配線。多様性はプロンプト＋独立生成で担保。
- integrator には3視点を **A/B/C に匿名化**して渡す（順序もシャッフル）。
- 各 lead 出力の `STANCE:` 行と `【...】` ブロックは軽くパースして integrator 入力に整形（fshiori/magi の POSITION タグ方式）。
